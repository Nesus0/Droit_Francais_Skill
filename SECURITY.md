# Politique de securite

## Signaler une vulnerabilite

Ne publiez pas de vulnerabilite exploitable dans une issue publique. Ouvrez un
signalement prive via GitHub Security Advisories pour ce depot, avec :

- une description et un impact;
- les versions ou commits concernes;
- les etapes de reproduction minimales;
- une preuve de concept non destructive;
- une proposition de correction si elle est connue.

N'incluez aucun secret, jeton, donnee personnelle ou contenu confidentiel. Les
tests doivent rester limites a des environnements et comptes autorises.

Les demandes concernant le droit ou les sources juridiques ne constituent pas un
signalement de securite; utilisez les issues publiques pour ces questions.

## Limites de securite

Le depot ne fournit ni service web ni traitement de dossiers. Les sorties LLM,
les integrations fournisseurs, la conservation de documents et les appels API
reels restent hors du perimetre des validateurs locaux. Ne transmettez jamais de
donnee confidentielle a une campagne de test sans autorisation et cadre adapte.
